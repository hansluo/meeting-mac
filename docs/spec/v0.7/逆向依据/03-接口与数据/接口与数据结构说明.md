# 接口与数据结构提取

本目录基于主程序和包内 Helper 的静态证据，不含运行观察。JSON 每项记录文件偏移或已有证据行号。主程序 Dart 字符串的文本与对应字节及 SHA-256 已逐项核对。Helper 来自现有证据目录内的已解包成员。

## 已精确恢复的本地业务协议

Helper 文件偏移 `0x3138698` 起的 3578 字节是可完整按 protobuf wire 格式解析的 `research/xeno/labs/foresight/launch_agent/proto/rag_service.proto` 文件描述符。已解出 22 个消息、45 个字段和 11 个 RPC；保存于 `rag-service-descriptor.json`，所有字段含编号、类型、重复标记、oneof 和来源偏移。`rag-service.descriptor.bin` 保留原始描述符。`rag-service-readable.proto` 是便于阅读的重建文本，不是源代码；没有重建文件自定义 options，也未执行 protoc 编译验证。

| 方法 | 请求 → 响应 | 可确认的契约 |
|---|---|---|
| IndexDocument | IndexRequest → IndexResponse | 文档 ID、content、user_id、切块 token 上限/重叠、图片 bytes、MIME；返回 success/error_message |
| RetrieveContext | RetrieveRequest → RetrieveResponse | query、max_results、min_similarity_score、user_id、allowed_document_ids；返回 chunks |
| UpdateModelPaths | UpdateModelPathsRequest → UpdateModelPathsResponse | embedding 和 SentencePiece 路径、use_gpu、cache_dir |
| DeleteDocument | DeleteRequest → DeleteResponse | document_id、user_id |
| Encode | EncodeRequest → EncodeResponse | text → repeated int32 tokens |
| ChunkText | ChunkTextRequest → ChunkTextResponse | text/max_tokens_per_chunk → repeated string chunks |
| TruncateText | TruncateTextRequest → TruncateTextResponse | text/max_tokens → truncated_text |
| ComputeEmbedding | ComputeEmbeddingRequest → ComputeEmbeddingResponse | text → repeated double embedding |
| ComputeImageEmbedding | ComputeImageEmbeddingRequest → ComputeEmbeddingResponse | image_bytes → 同一 embedding 响应 |
| ComputeAudioEmbedding | ComputeAudioEmbeddingRequest → ComputeEmbeddingResponse | audio_bytes → 同一 embedding 响应 |
| Ping | PingRequest → PingResponse | 空请求 → success/version |

`Query.query` 是 oneof，两个分支为 `text_query` 和 `audio_query`。`RetrievedChunk` 包含 text、double relevance_score、document_id、mime_type。所有 RPC 的描述符 streaming 标志均未设置，按 protobuf 默认值是 unary。以上来自 descriptor 的结构解码，不是凭方法名猜测。RPC 容器来源偏移 `0x3138cf3`；方法与字段各自偏移见 JSON/proto。

虽然主程序字符串只发现 9 个本地 RPC 路径，Helper 描述符明确保存了全部 11 个。不能据此把 ChunkText/ComputeAudioEmbedding 标为 UI 可达功能，也不能把主程序字符串缺失当作服务器不支持。

## 存储

Helper 精确 SQL 显示两张 metadata 表，原文及完整 CRUD SQL 见 `helper-business-statements.sql`。

```sql
CREATE TABLE IF NOT EXISTS documents (id TEXT PRIMARY KEY, content TEXT, userId TEXT, maxTokensPerChunk INTEGER, chunkOverlap INTEGER, mimeType TEXT, imageBytes BLOB);
CREATE TABLE IF NOT EXISTS settings (key TEXT PRIMARY KEY, value TEXT);
```

来源为 Helper 字符串证据 `helper-strings.txt:113443-113450`，原二进制偏移见 JSON。这两张表的字段定义是精确提取；没有打开用户数据库，不能声称确认数据库当前实际 schema 或内容。

Helper 提供命令行参数字符串 `<socket_path> <storage_root_path>`（证据行 154732）及 `/agent_metadata.db`（154737）、`/rag_vector.db`（157808）、`/foresight_helper.log`（154733）。这些字符串和监听 Unix Socket 的日志（154740）共同支持“通过调用者传入的 Unix Socket/存储根目录启动本地服务”的架构推断；完整路径、目录创建权限、失败重试尚未恢复。

Helper 保存 node_embeddings 的 cosine similarity 查询（154743）及通用向量查询模板（157954、157955、158912）。因此可确认二进制包含基于 SQLite 向量 BLOB 的相似度检索 SQL。没有精确恢复向量表完整 CREATE TABLE、向量维度、编码格式、索引方案及调用链。WAL/NORMAL/事务字符串来自通用 SQL 层，存在不等于所有业务数据库都采用它们。

主程序的 Drift 生成表类候选包括 SourceText、ContextSourceText、EventTranscript、EventInsight、EventDocument、Notes、Contacts、ProcessedUri、DriveFileSubscription、DocumentEntities、DocumentEntityState、DocumentLabels、DocumentClusters、DocumentEmbeddings、DocumentEdges、Nodes、Edges、NodeEmbeddings、GraphRagDocumentState、KeyValueEntries。35 条相关类/模块字符串逐项记录来源偏移。**这些是模型存在的证据，不是完整数据库表结构**；不能给它们拼凑主键、外键、索引或字段类型。`database.sqlite`、`key_value.sqlite`、`key_value_store.sqlite` 同样只证明文件名字符串存在，真实数据目录和用途需核对调用点。

## 原生推理与语音边界

主程序保留 37 个明确导出 C 符号，原文及符号证据行号见 JSON 的 `native_export_symbols`。虚拟地址不能直接当作文件偏移。

- 推理引擎：`litert_lm_initialize_engine`、`litert_lm_shutdown_engine`。
- 会话：create_conversation、create_conversation_v2、clone_conversation、delete_conversation。
- 生成：conversation_send_message、send_message_stream、send_pending_message、conversation_cancel_process、free_response_string。
- 另一套 session 接口：engine_create_session、session_generate_content_json、delete_session。
- 语音：OdmlCreateSpeechPipelineFromProto、CreateSpeechProcessorLiteRtLm/FromProto、CreateSpeechProcessorLlmEngine/FromProto、SpeechProcessorTranscribe、FinishStream、Prewarm、DestroySpeechProcessor。
- 热词：SpeechPipelineGetBiasingDictionary、BiasingDictionaryAddPhrase、RemovePhrase、SetPhrases、DestroyBiasingDictionary。

## 立项时最关键的决定

以下是开发建议，不是提取结果。

1. 先定义本地 helper 的独立服务契约。原产品已提供明确的“导入—切块—embedding—检索”边界；MVP 可先做文本版本，音频/图片 embedding 延后。不要让 UI 直接承担所有模型生命周期。
2. 文档事实、向量索引与派生洞察分层保存。metadata 的 `document_id`/`user_id` 及检索过滤说明用户隔离和文档溯源值得在初版纳入；删除请求同时覆盖 metadata、向量与派生信息，避免残留。
3. 自主定义检索评价指标。原协议允许 max_results/min_similarity_score/allowed_document_ids，参数可调并不证明已有检索质量；建立召回、引用准确性、误召回和耗时评估。
4. 明确模型切换与重建索引策略。UpdateModelPaths 给出了模型/分词器路径、GPU、cache 参数，替换 embedding 模型可能使旧索引不可比；保存模型版本、向量维度和索引版本应是自己的设计。
5. 把取消、流式输出、语音预热和资源释放作为原生层接口要求。当前符号提供路线线索，但重新实现时选择自己可维护的公开引擎/API，制定并验证 ABI，不直接复用未解原型。
6. 云端功能逐个估算依赖。共享配置、外部网页抓取、GoLinks、文件订阅、FCM 都可能依赖原厂服务；立项时决定替代、删减或自建，而不是把现有 URL 当成可用基础设施。

## 未解问题

- 本地 RPC 处理函数真实路径、默认参数、异常语义、线程/并发限制。
- helper 启动/退出、Unix Socket 权限、版本检查、崩溃重启与 orphan 清理。
- 主程序完整 Drift 表字段、外键、迁移和派生状态更新规则。
- 图谱实体/边生成、聚类、Graph RAG 的算法和质量门槛。
- 向量实际维度、归一化、量化、缓存与过期实现。
- 云端 protobuf 消息、认证元数据、重试和缓存规则。
- 原生 FFI 完整签名和语音数据格式。

上述未知不会被 SDK 中无关的海量 protobuf 字段填补。本目录仅结构化恢复了一个明确属于本地业务的描述符。
