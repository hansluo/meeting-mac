# 同类产品立项建议与验收

以下全部是**自主方案**，依据静态观察形成，不能作为 Foresight 源码、实际规格或性能承诺。目标应是独立实现可靠的“会议与个人知识助手”，而非逐屏克隆。

## 产品决策

建议先锁定 macOS、一种主要转写语言、用户主动开始录音、手动本地文件导入、明确来源引用。首版完成录音→可靠转写保存→可回查纪要/行动项→引用资料问答的闭环。模型管理和故障恢复要纳入首版，因为没有它们便无法稳定交付核心能力。

第二阶段加入 Google Calendar 关联、Google Drive 增量导入、会前brief、历史会议检索、用户笔记增强。第三阶段再做会议中自动 query detection、主动sidecar、实体图谱与多路融合检索。这样可以先证明结果价值，再承担误触发、实时延迟、图谱维护和多模型驻留的复杂性。

关键决策变量是最低支持设备的内存/芯片、离线边界、每小时录音能耗与磁盘、模型首次下载时间、答案来源可追溯性、自动触发误报频率。当前逆向未给出可信性能值，必须用原型测量；不能拿提示词数量来估算工程量。

## 独立实现的最小工程分层

| 层 | 必须实现的职责 | 可简化之处 |
|---|---|---|
| 桌面与权限 | 录音控制、授权、系统音频/麦克风来源、睡眠唤醒、通知与错误恢复 | 首版不做复杂sidecar和全局热键 |
| 模型管理 | 版本清单、下载状态、文件校验、取消/恢复、就绪状态、内存预算 | 固定一个ASR/embedding/生成模型组合 |
| 转写存储 | 来源/时间/文本版本、稳定片段与暂定片段、去重、事务保存 | 暂不承诺真正说话人diarization |
| 摄取与同步 | 源标识、解析版本、修改指纹、任务队列、索引、删除、来源预览 | 首版只支持TXT/MD/PDF，复杂office分阶段 |
| 检索 | 时间/参会人硬过滤、向量召回、删除过滤、token预算、引用拼装 | 首版先结构化过滤+向量，图谱后置 |
| 任务工作流 | 纪要、brief、行动项、增强笔记、问答分别设输出协议 | 不追求单一提示词包打所有任务 |
| 数据治理 | 本地数据导出/删除、账号解绑、隐私边界、遥测开关 | 遥测首版只存本地诊断，不发正文 |

原产品模块与协议可作为拆分线索，但不应沿用其内部服务地址、产品身份、Google私有模型与不可分发组件。具体模型与库应独立选择，当前包不替代选型验证。

## 必须制定的数据契约

建议转写片段保存 `session_id/source/speaker_label/start_ms/end_ms/text/status/revision`；源文档保存 `source_id/uri/mime/modified_fingerprint/parser_version/deleted_at`；chunk保存 `chunk_id/source_id/position/content/hash/embedding_model_id`；生成结果保存 `task_type/model_id/prompt_version/input_revision/citations/output/status`；任务队列保存 `job_id/kind/idempotency_key/retry_count/next_retry_at/error_class`。

这些字段是自主设计，不是对 Foresight 真实schema的声称。必须能解释“这个答案用了哪一版材料”，并使重新嵌入、重复导入、删除和重试不破坏一致性。

## 立项前必须补齐的未知

1. 用最低支持设备实测 ASR 与生成并行时的RAM、实时率、TTFT、能耗；测40/90分钟会议，不能只测一分钟demo。
2. 音频权限与系统音频采集的实际可用性；测试不同耳机、蓝牙切换、被其他应用占用、静音。
3. ASR多语言/术语/噪声能力与模型可分发条件；下载服务与模型更新的运营成本。
4. 用户资料混合时检索的引用正确率、时间条件正确率、无证据拒答质量；不能只看流畅度。
5. 云集成的OAuth、增量同步、撤销、速率限制、删除与来源权限继承；不照抄原厂后台接口。
6. 模型/解析器/检索失败时的可恢复性与缓存策略；确保失败不会默默产出不完整纪要。
7. 网络访问与遥测实际载荷；对外声明须用实现与测试支撑。

## 验收场景

下列是建议的新产品验收条件，不是已经测过 Foresight 的结果。数值目标需产品负责人在设备实测后冻结；先规定可观测性与正确性。

| 场景 | 输入/故障 | 预期结果 | 证据 |
|---|---|---|---|
| 连续会议 | 40分钟双来源音频，多次暂停/恢复 | 无重复segment；每条保留时间和来源；结束可回查完整转写 | segment连续性与音频抽样对齐 |
| 暂定转写修正 | ASR把同一句改写两次 | UI更新同一片段；不生成三个独立片段；查询去重 | revision/dispatch日志 |
| 无音频自动停止 | 静音跨越已配置超时 | 显示停止原因；完成剩余写入与笔记；可手动恢复 | 状态机/结果版本 |
| 休眠与唤醒 | 录音中合盖，醒后换音频设备 | 按产品策略暂停或恢复；无后台假录音、无恢复风暴 | 状态和恢复次数 |
| 首次模型下载 | 断网、磁盘满、损坏chunk、用户取消 | 清楚显示状态；不把损坏文件当ready；重新下载不重复积累 | hash/下载账本 |
| 缺模型启动任务 | generation模型未就绪 | 禁用任务并指向下载；不输出伪结果 | readiness事件 |
| 文件导入 | 正常/超大/损坏/空/加密PDF | 明确接受或拒绝；失败源不标“已索引”；不冻结UI | ingestion任务状态 |
| 重复及变更导入 | 同一文件导入两次，再修改内容 | 不重复源与chunk；只保留有效版本 | source/chunk fingerprint |
| 来源删除 | 删除已在答案中引用的文件 | 新检索不命中；历史答案能提示来源已删除 | 删除墓碑与检索断言 |
| 模型切换 | 更换embedding模型 | 版本隔离；旧向量不可混算；回填可续做 | index generation |
| 时间与日程查询 | “下周与张三的会议”、跨周末/时区 | 结构化条件准确；不存在时直接说明；列表不遗漏匹配项 | ground truth事件集合 |
| 资料冲突 | 两文档给出不同结论 | 引用各自版本/时间；不把冲突编成唯一事实 | 输出引用与source revision |
| 长会议纪要 | 一个关键决策仅在末尾出现 | 所有主要决策被保留；行动项不捏造负责人/截止日 | 人工标注对照 |
| 当前事实查询 | 离线、web search关 | 明确资料不足；不隐式联网 | 网络记录 |
| 问答图像来源 | 检索返回图片但模型无vision | 降级说明或选择适配模型；不声称“看过图片” | 模型能力与输入模态 |
| 后台崩溃 | 守护进程重启/模型服务断连 | 有限重试、任务幂等；重连后恢复模型路径 | job_id与重连事件 |
| 隐私 | 本地问答、同步、web search、遥测分别触发 | 每入口边界与声明一致；正文不进入非授权链路 | 仅用合成数据的网络审计 |
| 数据清除 | 清除资料/账号解绑/重置 | 按产品范围删除原文、索引、缓存与凭据；不可只删UI列表 | 数据目录与索引审计 |

验收样本建议包含100个事实/时间/不存在信息问题、20份格式各异文档、5段真实噪声条件的合成或授权会议录音。输出错误类型和引用命中率，不用“用户觉得好用”代替数据。主动查询识别阶段另标注触发时机、应触发/不应触发片段及重复触发，以衡量召回与误报。
