# Foresight 产品机制与工程规格

本报告针对已安装应用进行只读静态分析，没有启动应用、读取个人工作数据、连接服务或验证实际交互。证据取自主 Mach-O 中的字符串与模块路径；503 条精选字符串已按文件偏移和 SHA-256 对原字节复核，详见 `产品机制证据.json`。模块名能证明构建包含相应常量，不能单独证明功能在当前版本可达。

标记规则：**观察**是字节中直接存在的文字；**推断**是由多个常量组合出的机制解释；**自主方案**是建议的新产品实现；**未知**是此次未恢复的运行时或源码细节。偏移均为 `/Applications/Foresight.app/Contents/MacOS/Foresight` 文件偏移，不是函数地址。

## 1. 产品闭环

**观察**：包含 Meetings、AI sidecar、Chat、Knowledge library、Document graph、Notes/Scribbles、Home dashboard 等业务模块。Home 子模块分别处理 upcoming events、recent meetings、attachment summary、transcript summary、action items、insight history、meeting search。

**推断**：核心是把会议转写、个人文件、日历与历史会议变为可检索上下文，然后在会议中主动提供答案、会前准备、会后笔记与行动项。立项时应把它理解为持续维护个人知识与会议上下文的桌面工具，提示词只是其中一层。

**未知**：模块是否全部开放，功能之间的精确导航、订阅与实验开关、默认账户状态。不能把 Flutter/Google SDK 带入的界面类或数百种本地化语言视为支持清单。

## 2. 会议实时链路

**观察**：`TranscriptManager`、`TranscriptBuffer`、`SpeakerIdManager`、`TextDeduplicator`、`PrefixStreamFilter`、`QueryDetectorOnDevice`、`QueryDispatcher` 模块和日志存在。

- `0x592ed40` 明文初始化日志为 `TranscriptBuffer: Initialized with maxWordCount=200, maxUiLines=4, fillGapMs=2000`。
- `0x594c5e0` 存在按 source 合并 transcript segment 的日志；`0x616db20` 是 embedding 模型变化触发处理的日志。
- `0x5ab4a10` 记录 query detection result；`0x5e28be0` 记录新查询分发；`0x615c950` 记录 QueryDispatcher 保留查询；`0x6210800` 记录检出查询后推进 history cursor。
- `0x5a16d80` 有 `cancelQueryDetectionDebounce`，`0x5d43d00` 有 `nonSpeechTagRegex`。
- `0x5fd5cd0` 明文表示转写的 server fallback 已移除，仅支持 on-device inference；不能因为存在 Gemini 服务类便宣称转写支持云回退。
- `0x5d49be0` 表示 sidecar 在既非转写状态且 TranscriptManager 未启动时忽略 queryStream。

**推断**：音频分流→本地 ASR→转写缓冲与前缀/非语音清洗→去重→本地问题识别→查询分发→上下文检索→sidecar 答案。Microphone 与 Remote 相关正则表明处理过这两类来源名称，但不能确认采集权限、音轨混合方式或说话人识别准确率。

**未知**：防抖时长、query 判定阈值、去重相似度阈值、history cursor 的实际范围、缓冲参数是否按场景覆盖、处理语种、音频采样率。业务正则原文另存 JSON；没有恢复调用顺序或正则标志。

## 3. RAG V1/V2 与关系查询

**观察**：`v2RetrievalEnabled`、`retrieveContextV1`、`_retrieveContextV2`、V1/V2 策略日志同时存在。V2 记录 Vector Result、Graph Result、Final Chunk；其他日志包括 Graph results count、Vector results count、Combined chunks count、Reranked chunks count、在内存中查询 transcript embeddings、注入 fast-path relational context、过滤已删除文档。

可定位常量：V2 开关 `0x594b130`；V2 策略 `0x5aa6420`；V1 策略 `0x607f980`；图谱计数 `0x5c6b4b0`；合并计数 `0x5e2d150`；重排计数 `0x6163810`；关系上下文注入 `0x5fbfb60`；删除过滤 `0x6163400`。

**推断**：检索组合向量搜索、图谱结果、当前转写与结构化会议元数据；V2 可能强化图谱融合，再重排与去重。关系查询另有 `RelationalIntentDetector`、`ScheduleWindowParser`、`RelationalMetadataResolver`、`MeetingMetadataFormatter`，避免将日历时间条件完全交给向量检索。

**观察**：英语规则包括时间词、过去会议、未来会议、备会意图、参会人/主题抽取、决策/批准类问题。JSON 中保留 75 条相关正则。例：`0x5d2c2d0` 覆盖 `show my / list my / my upcoming / check my calendar`；`0x5be6020` 包含 today/tomorrow/yesterday 与周月年词；`0x60b8e20` 包含 decided、action item、deadline、blocker、risk、budget。

**未知**：V1/V2 默认开关、图谱扩展跳数、实体 extraction 输出协议、topK/minSimilarityScore 的真实值、重排算法/权重、全文索引与向量表的调度次序。见到字段 `topK`、`minSimilarityScore`、`chunkOverlap` 不等于知道常量值。

## 4. 文件摄取与知识维护

**观察**：拖放文案 `0x5eac060` 明确 text/PDF/DocX 将在本地索引；`0x59a2520` 文案明确选中文件限制 50 MB。`0x60cdca0` 与 `0x5e943c0` 指向 Downloads/Documents/Desktop 发现候选后由用户选择导入。包含 local file discovery/fetcher/processor，以及 document manager/downloader/embedder 与 fetcher factory。

**观察**：解析器包中包含 PDF、DOCX、XLSX、PPTX、TXT、MD、HTML、RTF、ODT、EPUB、ZIP 等模块。链接匹配正则包含 pdf/txt/docx/xlsx/pptx/md/log。这只证明解析/链接识别组件被打包；不应将其直接写成用户可导入的完整格式清单。显式拖放文案优先证明 text/PDF/DocX。

**观察**：日志区分本地读取失败、权限/文件不存在、解析失败、不支持类型、Google Drive canDownload 权限、未修改跳过下载、未缓存仍下载、显式删除跳过、embedding 缺失回填、embedding 模型切换后重新嵌入。DOCX 本地解析失败后存在 OdmlService fallback 日志 `0x5b01f40`；此 fallback 的执行位置与网络边界未证实。

**推断**：摄取并非一次性“文本入库”。必须保留源 URI、修改状态、缓存、下载状态、索引状态、嵌入模型版本、删除语义与来源预览。原产品有 SourcePreviewService、document graph 与原文导航，答案需要能回到来源。

**未知**：50 MB 是否所有入口统一约束、文件夹遍历深度、批量限额、加密PDF/OCR处理、图片存储策略、解析器对复杂表格的覆盖率、Drive 同步频率。

## 5. 本地模型、下载与守护进程

**观察**：界面文案有 Gemma 4 E2B/E4B/12B 下载；expert models 文案指出 speech recognition/query detection/text embedding 为 Required。`0x5c293a0` 显示本地 EmbeddingGemma 索引。模型 path observer 与 RagOrchestrator 向 daemon 发送模型路径、等待 readiness、重连后重新初始化等日志存在。

**观察**：ChunkDownloader 具有 chunk 开始、完成、重试、超时、尺寸不一致、NonRetryableDownloadException 等日志。`0x5afed60` 初始化 daemon 超时日志明确 15s。`0x61c0f00` ChatService 的本地默认 maxTokens 文案明确 4096，另有从 model config 取 maxTokens 的路径。

**推断**：模型下载及 readiness 是首屏功能的前置门槛；下载模块要支撑分块、状态追踪、校验、失败分类、已存在模型查找、配置与路径切换。后台 RAG daemon 与 UI 分进程，初始化依赖模型路径就绪。

**未知**：模型商用授权、实际模型权重与SHA、RAM/磁盘/芯片门槛、运行后端选择、并发预算、分块大小、下载重试次数、断点续传是否实现、下载地址配置的有效性。日志里“分块/partial”只能证明相关处理常量，不能证明完整可靠行为。

## 6. 睡眠、录音与故障恢复

**观察**：系统睡眠与唤醒检测；醒后 transcription service re-warm；睡眠期间 scheduled meeting 已结束时终止录音；静音/无音频达到 inactivity timeout 后停止并完成笔记；native inactivity timeout 同步；inference 服务 readiness 检查与受限 recovery。

- 音频恢复 `0x5a3ea70` 明确最多 2 次/30s；`0x5d7b270` 防并发恢复；`0x5d4aba0`/`0x5ea9b20` 区分成功/失败。
- `0x61e62b0` 明确 recorder warning interval 30m。
- `0x596a1c0` 表明 meeting ended 超过 15m 后跳过 stale notification。
- `0x5ce3700` 有 LiteRT-LM recovery exceeded limit 日志，但未恢复 limit 数值。

**推断**：桌面 app 生命周期是核心难点，状态至少需区分未启动/预热/录音/暂停/结束/恢复中/失败。音频故障和推理故障应分开处理，避免恢复循环和重复创建实例。

**未知**：静音默认时长、睡眠超时阈值、音频恢复触发条件、最后未写入的转写在故障时能保留多少。

## 7. 聊天、笔记与长文生成

**观察**：ChatService 有 pre-retrieval、token threshold exceeded、tokenizer 不可用退回 word count estimates、首次 token 时延、图像召回后启用 vision modality/重新初始化 handle、图像压缩失败等日志。`NotesEnhancer`、`MapReduceExecutor`、`TranscriptAggregator`、`TranscriptEmbeddingManager`、chat history 与 Markdown 笔记/导出存在。

**推断**：聊天前先检索并控制 token 预算；长会议通过分块/部分摘要/合并生成最终纪要；新录音可增量更新 meeting brief；notes enhancer 用相关转写片段补全用户速记。每个生成工作流需要单独任务协议、引用规范与覆盖性验证，而非一个全能system prompt。

**未知**：聊天历史裁剪策略、context window 数值、maxTokensPerChunk/chunkOverlap 数值、摘要刷新频率、图像数量限制与实际视觉模型能力。

## 8. 网络边界

**观察**：`0x5abafe0` 声称 Drive/Calendar 同步导入用网络，分析处理留在设备；`0x5fa0dc0` 声明 Drive/Calendar 导入、可选web search（default off）、去标识usage数据需要联网。存在 GeminiServiceModel/远程tokenizer/后台服务协议常量。

**解释限制**：这些是产品声明与打包证据，不是抓包结论，不能据此保证零外传。仍需动态验证每个入口、异常 fallback、遥测载荷、后台服务的实际内容。当前不读取真实账户数据、不调用供应商服务。
