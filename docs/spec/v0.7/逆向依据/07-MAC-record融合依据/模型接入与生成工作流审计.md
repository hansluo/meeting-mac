# MAC-record 模型接入与生成工作流审计

固定仓库 `hansluo/MAC-record`，commit `ad53c5740e59498d6c9869c04027c2daddd1b48d`。只读所提供源码快照，不运行程序或模型，不改仓库。选择性源码快照中五个文件已与 verified-source-manifest 的固定 commit Git blob SHA 和 SHA-256核对。JSON 中每项包含源码路径、commit 和准确行号；本报告以 M01–M22 对应这些证据。

结论是现有生成服务可以复用为第一版 OpenAI-compatible 文本调用，但不足以直接承接 Foresight 的流式问答、行动项抽取和严格本地路由。模型探测得到的是服务候选，没有证明生成、有效上下文、结构化输出、tools 或 Qwen 实际性能。Qwen/FunASR 的 ASR 适配与本地 Qwen 生成适配是两层，不能把一层探测结果当成另一层能力。

## 融合后的新要求

以下均为新系统规格，不声称 MAC-record 已实现。

### R01 显式模型路由

profile至少包含 `id, label, execution(local/cloud), protocol, endpoint, modelID, credentialRef?, contextWindow, contextSource, capabilities, extraParameters`。cleanup/summary/QA/entities/actions各自指定profile；任务创建时冻结modelID、endpoint和dataPolicy。选中ID失效必须报配置错误，禁止改选first。local_only只允许loopback生成请求，本地服务停止、超时或模型被移除时保留可重试状态，绝不隐式请求云端。依据 M14、M20。

默认云关闭。用户明确选择云profile后才能发送该任务的资料；记录资料范围/provider和任务路由。选择云模式不能将其他local_only任务改为云端。

### R02 将发现与能力验证分开

MVP本地Qwen通过已启动的OpenAI-compatible runtime接入，云使用独立profile。第一版协议只承诺 `openai_chat_completions`。其他原生API需独立adapter，不能输入URL就视为支持。

列表探测标记discovered，实际标准请求通过标记basic_chat_tested。结构化JSON、stream/cancel、中文纠错、上下文分别记录unknown/verified/unsupported、endpoint/model/runtime版本及验证时间。连接测试须用与正式调用一致的payload；`enable_thinking`、`max_tokens`或`max_completion_tokens`仅按profile验证的能力发送。依据 M02、M04–07、M21。

### R03 云API Key的实际落地

设置页需要label/provider/modelID/HTTPS endpoint和Secure输入API Key，以及保存、测试、替换、删除Key操作。凭证直接以macOS Security框架GenericPassword持久化，建议service为新appID.LLM、account为profileID、Synchronizable=false、Accessible=AfterFirstUnlockThisDeviceOnly。

处理SecItemAdd/Update/CopyMatching/Delete的OSStatus；保存失败不能显示成功。JSON仅保存credentialRef，不保留apiKey字段，导出和序列化统一排除secret。Key仅在请求时临时进入内存及Authorization，日志/诊断/导出脱敏。空输入更新不暗示删除，提供明确删除Key操作。provider/endpoint改变时禁止复用其他profile的凭证。必须测试清空、替换、删除、重启读取及Keychain写入失败。依据 M15–17、M22。现代码确实写入系统Keychain；新要求是补齐失败处理、替换原子性和UI结果链路。替换已有Key用SecItemUpdate，不先删除旧Key；存储失败保留旧凭证与配置，legacy迁移仅在安全存储成功后删除旧文件。

### R04 流式、超时与取消

统一GenerationRequest包含jobID、taskType、modelID、deadline和cancellation。SSE适配处理跨网络分片、增量内容、done/error/cancelled；取消须停止网络与全部map/merge任务，不能被catch转成成功。区分connect、first-token、idle、total deadline，local/cloud分别配置。保存原始转写和已完成分段checkpoint，取消保留partial但最终状态cancelled。依据 M04、M18、M20。

### R05 长文预算与可靠完成状态

context只接受用户显式值或匹配当前模型的已验证metadata，不取其他模型兜底。按system/input/output/reserve总token预算切分，取消4000字符和4096输出的强制最小值；未知context标估算。context错误在最大重试次数和最小token限制内缩小输入及输出；429/5xx在同profile有限退避，不改provider。解析usage、finish_reason、截断和空输出，返回完整/部分/失败状态而不是仅String。依据 M08–12。

整合阶段无法完成时显示“部分结果/拼接结果”，不能当成完整纪要成功。通过prompt要求“100%保留”不构成事实完整性保证。

### R06 Foresight任务化prompt与证据链

原ASR与纠错版本分别保存。cleanup、summary、overview、QA、entities、actions分别定义prompt/schema版本，消除“禁止summary”默认prompt被用于summary的冲突。行动项带sourceRecordingID、segmentID、起止时间和原文引用；分段产生结构化事实与引用，再跨段合并去重。Qwen/FunASR通过独立ASR协议进入同一转写事实层，不与生成共享模型能力或secret假设。依据 M11、M13、M18、M21。

## 验收重点

- 本地runtime停止后local_only生成没有任何云请求。
- 指定模型失效报配置错误，不自动选第一项远程模型。
- 列表可发现但不支持正式payload的模型不能显示可用。
- JSON/导出/日志不含API Key；Security写失败为用户可见错误。
- map/merge期间取消保留checkpoint并显示cancelled，不显示完整成功。
- 4k/8k模型输入、system和输出预算不能超过已验证窗口。
- 429有限重试使用同profile；不支持extra参数不能误认为context溢出。
- ASR原文保留；清洗和summary是不同任务与prompt。

当前Qwen具体模型、运行时、量化、RAM、延迟和能力，以及设置UI完整链路和实际Keychain失败恢复行为仍未运行验证。需要后续选定环境的运行验证关闭，不能以README或模型探测代替。
