# Meeting Mac 原生工作区设计基线

这是自主实现的界面方案，不是声称已恢复的 Foresight 像素规格。参考依据是逆向包中已核验的 Meetings、Knowledge library、Chat、Notes、Home 等业务模块；原应用的精确导航、默认开放状态和布局尚未由静态证据证明。

## 方向

沿用当前 SwiftUI 原生界面，按 huashu-design 的局部延展方式实施。会议、资料和对话是最终主线；当前只呈现具有真实可操作流程的入口，随对应实现逐步加入其余功能。使用自有 Meeting Mac 名称和系统符号，不复制第三方图标或身份标识。

- 系统字体：侧栏13pt、正文15–16pt、长文17pt，页面标题22pt；技术来源信息降为12pt次要文字。
- 使用系统窗口/分组背景和系统蓝强调色，支持系统深浅色；间距以8/12/16/24为单位，卡片圆角10，避免装饰渐变和大面积阴影。
- 原生侧栏约200pt；资料页使用列表与详情两栏。主窗口最小宽度约960pt，较窄时可折叠侧栏，不做移动端设备框。
- 状态用明确中文说明。只有真实字节进度才显示百分比；解析、索引和模型加载使用阶段说明与不定进度。

## 首个资料工作流

1. 侧栏保留已可用的音频转写，加入真实资料库。进入资料库显示已保存来源、解析/索引状态、版本及更新时间；没有资料时提供导入TXT/Markdown/PDF的明确入口。
2. 系统文件选择器导入。任务期间显示处理阶段和取消，防止重复开启；模型未准备时引导已有的内置模型准备，不要求本地路径或Python。
3. 成功后显示保存的文本快照，明确原文件修改不会自动改变该版本。失败或取消保留上次有效内容与选择，不将未完成的向量称为已索引。
4. 查询范围让用户看得见。可选全部已启用资料或当前选择；空选择不自动扩大范围。结果显示来源标题、片段原文和可定位页码/文本范围，点击回到已保存快照位置。
5. 此时结果称为检索片段。带回答与引用的对话在生成route和引用验证接通后启用，不能用片段列表冒充完整RAG问答。
6. 删除操作有明确确认及范围说明，处理中删除/撤权的来源不能被迟到任务重新激活。跨来源/账号范围由持久化层约束，不能仅依靠列表过滤。

## 后续真实入口

DeepSeek设置使用预填且可编辑的地址/模型，以及安全输入框和Keychain引用。测试连接与保存分开，临时测试不先保存Key；修改配置使旧探测失效。默认只上传生成任务所需的文字与引用片段，录音仍走本地ASR。

会议页在持久化会议与采集管线完成后加入录制、暂停、结束、原音频、转写版本、笔记与纪要。日程、备会和主动助手同样随真实业务入口接入，不以空页作为交付。

## 验证

控制器以可注入业务操作验证开始/失败/取消/迟到结果、选择与旧内容保留、任务排空和错误恢复。GUI使用已生成的合成资料验证导入、重开、检索、来源定位和删除排除；检查长中文、emoji、深浅色与窄窗口溢出。自动化工具不可用时，保留具体未验项目，源码审查不能替代点击验收。
